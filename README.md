# KRASNOV Estimate MVP

Рабочий прототип для части 3 тестового задания AI-инженера: пользователь описывает объект текстом или голосом, получает предварительную стоимость достоверно рассчитываемых работ и список недостающих данных. Результат можно без повторного ввода открыть в Telegram-боте.

## Как устроено решение

1. Пользователь вводит описание или диктует его через микрофон; распознанный текст можно проверить и исправить.
2. OpenAI извлекает из описания только явно названные параметры в строгую JSON-схему.
3. Обычный TypeScript-код сопоставляет работы с локальным прайсом и выполняет арифметику без участия LLM.
4. Неизвестные объёмы не оцениваются. Работа выводится в блоке «Требуется уточнить» и не влияет на итог.
5. Для Telegram создаётся короткий подписанный токен с проверенными параметрами. Бот проверяет подпись и повторяет расчёт тем же калькулятором.

Во внутреннюю JSON-базу загружены все 114 позиций из 18 разделов [открытого прайса компании «РемКонтора»](https://remkontora.ru/czeny/), проверенного 2 сентября 2026 года. Цены указаны «от», не являются офертой и включают только работы. Каталог можно обновить командой `npm run prices:sync`.

## Локальный запуск

Требуется Node.js 20.9 или новее.

```bash
npm install
cp .env.example .env.local
npm run dev
```

Откройте `http://localhost:3000`.

В отдельном окне терминала запустите Telegram-бота в локальном режиме:

```bash
npm run bot:dev
```

После расчёта нажмите кнопку Telegram и запустите бота. Он получит подписанные параметры через long polling и пришлёт подробную смету; публичный webhook для локальной проверки не нужен.

Для расчёта заполните в `.env.local`:

```env
OPENAI_API_KEY=...
OPENAI_MODEL=gpt-5-mini
```

Ключ используется только серверным обработчиком и не попадает в браузер. Реализация использует Responses API и Structured Outputs согласно [официальной документации OpenAI](https://developers.openai.com/api/reference/cli/resources/responses/methods/create).

## Подключение Telegram

1. Создайте бота через `@BotFather` и получите токен.
2. Добавьте в Vercel Environment Variables:

```env
TELEGRAM_BOT_TOKEN=...
TELEGRAM_BOT_USERNAME=имя_бота_без_собаки
TELEGRAM_LINK_SECRET=случайная_длинная_строка
NEXT_PUBLIC_APP_URL=https://ваш-домен.vercel.app
```

3. После production-деплоя зарегистрируйте webhook, выполнив один запрос (подставьте значения локально, не сохраняйте токен в репозитории):

```bash
curl "https://api.telegram.org/bot<TELEGRAM_BOT_TOKEN>/setWebhook?url=https://ваш-домен.vercel.app/api/telegram"
```

Ожидаемый ответ: `{"ok":true,"result":true,...}`. После этого кнопка результата открывает бота с подписанным параметром `/start`; бот присылает подробный расчёт.

## Развёртывание на Vercel

Импортируйте репозиторий в Vercel, добавьте перечисленные переменные окружения и выполните production deploy. Никакие ключи нельзя добавлять в git. Для публичного демо предусмотрены ограничение длины текста и базовый лимит запросов на IP; для постоянной эксплуатации нужен внешний rate-limit storage.

## Проверка

```bash
npm test
npm run lint
npm run build
```

Основные сценарии проверки:

- Пол 45 м², стены 110 м², санузел 5 м², кварцвинил, плитка и покраска: все известные работы рассчитываются; для потолка используется площадь пола 45 м².
- Пол 80 м², стены 180 м², санузел 12 м², ламинат: рассчитывается 68 м² укладки вне санузла.
- При обязательных площадях и описании «светлые стены и хороший пол» система не выбирает материалы самостоятельно и запрашивает уточнение.

## Что было сложным и что делать дальше

Главная сложность — корректно работать с разными единицами измерения. Для позиций в м² система использует площадь соответствующей поверхности, а для погонных метров, штук, точек, комплектов и модулей требует отдельный объём. Прайс, формулы и итог остаются в детерминированном коде и покрыты тестами.

Следующий шаг — заменить публичный каталог внутренними расценками KRASNOV, добавить загрузку проектной документации и измерять конверсию сценария «сначала польза → затем Telegram» относительно обычной формы заявки.
